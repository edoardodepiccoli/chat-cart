# Repo Simplification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the repo down so a junior can read it in an afternoon: replace the cart sync folder with two short files, drop visit history, delete dead code, and give files clear names.

**Architecture:** The cart becomes `chat-widget/src/cart.ts` (module state, AJAX Cart API calls, a small fetch/XHR wrapper that re-reads `/cart.js` after theme writes) and `chat-widget/src/cartEvent.ts` (the Shopify standard `shopify:cart:lines-update` event for the theme). The server stops resolving visit history and looks up only the current page's title. Everything else is deletion and renaming.

**Tech Stack:** TypeScript, React 18, Vite (IIFE widget build), Vitest with happy-dom, React Router app on Shopify, Vercel AI SDK, Zod.

**Spec:** `docs/superpowers/specs/2026-10-21-simplify-design.md`

## Global Constraints

- No new dependencies, no new patterns. Prefer deleting code over rewriting it.
- No race-condition handling for cart reads: the last answer to arrive wins.
- One cart write at a time: every cart button is disabled while `pending !== null`.
- The theme event is `shopify:cart:lines-update`, always with `action: "update"` and `context: "chat"`.
- After every commit: `npm test`, `npm run typecheck`, `npm run lint` and `npm run widget:build` pass.
- Commit messages: Conventional Commits, no `Co-Authored-By` trailer (CLAUDE.md).
- Work on branch `refactor/simplify` in the main checkout, no worktrees (`shopify app dev` breaks in worktrees).

## Review Focus

1. A theme `fetch` that rejects (offline): the theme gets the same rejection and no re-read happens. Test in Task 5.
2. A theme cart write under a locale root (`/it/cart/add.js`) or passed as a `Request` object: it triggers a re-read. Test in Task 5.
3. A theme cart write Shopify refuses (422, sold out): the theme gets the 422 response unchanged and no re-read happens. Test in Task 5.
4. An unknown currency or a theme listener that throws: `notifyTheme` does not throw, so the widget still shows the cart. Test in Task 4.
5. An old cached widget bundle that still sends `history`: the server accepts the request. Test in Task 2.

  1. a `started` flag guard;
