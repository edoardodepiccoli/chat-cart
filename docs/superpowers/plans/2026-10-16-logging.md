# Readable Logging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every server request, agent step, tool call, context resolution, suggestion, teaser, save and widget failure is logged as colored, detailed, skimmable terminal lines grouped by conversation and request.

**Architecture:** A dependency-free logger in `app/log/`: pure formatting and tool summaries, a level-filtering core with a replaceable sink, and an `AsyncLocalStorage` request context that stamps `conv=`/`req=` on every line. Routes are wrapped once; agent, tools, context, suggestions, teasers and conversations call the logger at their existing callbacks and catch sites. The widget reports four failure kinds through the existing events endpoint.

**Tech Stack:** Node `AsyncLocalStorage` and `util.styleText`-free ANSI codes, React Router 7 routes, Vercel AI SDK v7 callbacks, zod 4, vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-logging-design.md`

## Global Constraints

- No new dependencies.
- No `console.log` / `console.error` in `app/` outside `app/log/`.
- Never log access tokens, session objects or request headers.
- `LOG_LEVEL`: `debug | info | warn | error`, default `info`. `LOG_FORMAT`: `pretty | json`, default `json` when `NODE_ENV=production`, else `pretty`.
- Colors off when stdout is not a TTY or `NO_COLOR` is set; `FORCE_COLOR` forces them on.
- Level padded to 5, tag padded to 7, 2 spaces of indent per depth, message column padded to 24 characters.
- Quoted shopper/model text cut at 160 characters with `…`.
- `ms` yellow at ≥ 2000, red at ≥ 5000.
- Tag colors: `chat` blue, `context` cyan, `agent` magenta, `tool` green, `suggest` yellow, `teaser` yellow, `db` gray, `events` white, `client` red, `webhook` blue, `server` red.
- `conv` printed as its first 5 characters, `req` as 4 hex characters.
- Every task ends with `npm run typecheck && npm run lint && npm test && npm run widget:build && npm run build` green and prettier on changed files.
- Commits end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A tool throws (e.g. `showProducts` with no valid handles) → the tool line shows `⚠ error "<message>"` and the turn still ends with one `■ done`. Test in Task 4.
2. The chat stream errors after the route returned → `ERROR agent stream failed` and exactly one `■ done status=error`, never two `done` lines. Test in Task 2 (`endsLater` + `endRequest` twice logs once).
3. A payload contains a circular or huge object at `debug` → printed without throwing (fallback to `[unserializable]`) and JSON output stays one line. Test in Task 1.
4. A widget `client_error` arrives for a conversation that was never created (`conversationId: null`) → logged at `ERROR`, not saved, response 204. Test in Task 6.
5. Shopper text containing newlines or ANSI escape sequences → printed on one line with escapes stripped, so a shopper cannot break or recolor the log. Test in Task 1.

### Task 1: Formatter and logger core

**Files:**
- Create: `app/log/format.ts`, `app/log/logger.server.ts`
- Test: `app/log/format.test.ts`, `app/log/logger.test.ts`

**Interfaces:**
- Produces (`app/log/format.ts`):
  - `type Level = "debug" | "info" | "warn" | "error"`
  - `type Tag = "chat" | "context" | "agent" | "tool" | "suggest" | "teaser" | "db" | "events" | "client" | "webhook" | "server"`
  - `type Fields = Record<string, string | number | boolean | undefined>`
  - `type LogEvent = { time: Date; level: Level; tag: Tag; message: string; detail?: string; quote?: "shopper" | "model"; depth: number; edge?: "start" | "end"; fields: Fields; ctx?: { req: string; conv?: string; route: string }; payload?: unknown }`
    - `message` is the label column (`step 0`, `shopper says`); `detail` the free text after it (`"Vitamin C Serum" (serum)`); `quote` wraps `detail` in quotes, cuts it at 160 and styles it bold (shopper) or italic (model).
  - `formatPretty(event: LogEvent, options: { color: boolean }): string` — may return several lines when `payload` is set (indented JSON block, dim); a leading empty line when `edge === "start"`.
  - `formatJson(event: LogEvent): string` — one line `{ time, level, tag, message, detail?, depth, fields, conv?, req?, route?, payload? }`.
  - `clean(text: string): string` — strips ANSI escapes and replaces `\r`/`\n` with a space.
- Produces (`app/log/logger.server.ts`):
  - `type LogOptions = { detail?: string; quote?: "shopper" | "model"; depth?: number; edge?: "start" | "end"; payload?: unknown }`
  - `log.debug | info | warn | error(tag: Tag, message: string, fields?: Fields, options?: LogOptions): void` — `payload` is kept only when the level is `debug`.
  - `setSink(sink: (line: string) => void): () => void` — replaces stdout writer, returns a restore function (tests).
  - `setContextProvider(provider: () => LogEvent["ctx"]): void` — called by Task 2.
  - Reads `LOG_LEVEL`, `LOG_FORMAT`, `NO_COLOR`, `FORCE_COLOR` at each call (cheap; lets tests set env).

### Task 2: Request context and route wrapper

**Files:**
- Create: `app/log/request.server.ts`
- Test: `app/log/request.test.ts`
- Modify: `app/entry.server.tsx` (`console.error` → `log.error("server", "render failed", { error: message })`), `scripts/dev.sh` (`export FORCE_COLOR=1` before `shopify app dev`)

**Interfaces:**
- Consumes: `log`, `setContextProvider` (Task 1).
- Produces:
  - `withRequestLog<A extends { request: Request }>(route: string, handler: (args: A) => Promise<Response>, options?: { endsLater?: boolean }): (args: A) => Promise<Response>`
    - logs `▶ <METHOD> /<route>` (tag from route: `chat`, `teaser`, `events`, `webhook`) at depth 0 with `edge: "start"`;
    - on return: `■ done status=<n> ms=<n>` (edge `end`) unless `endsLater`;
    - on a thrown `Response`: warn `rejected status=<n>` then `■ done`, rethrow; on any other throw: error `failed error="<message>"` then `■ done status=500`, rethrow.
  - `setConversation(id: string): void` — sets `conv` in the current context.
  - `endRequest(status: number | "error", fields?: Fields): void` — logs `■ done` once per request (later calls are no-ops).
  - `logRejected(tag: Tag, issues: z.core.$ZodIssue[]): void` — warn `invalid body` with one depth-1 line per issue: `<path>: <message>`.
  - `requestTag(): Tag` — the current route's tag, for callers that log at route level.

### Task 4: Agent, tools, context and suggestions logging

**Files:**
- Modify: `app/agent/agent.server.ts` (`runAgent`, `onStepEnd`, new `onError`; remove `DEBUG` and `console.log`), `app/agent/tools.server.ts`, `app/agent/context.server.ts`, `app/agent/suggestions.server.ts`

- Test: `app/agent/logged.test.ts`, `app/agent/context.test.ts` (extend)

**Interfaces:**
- Consumes: `log` (Task 1), `summarizeToolResult`, `formatInput` (Task 3).
- Produces:
  - `logged<I, O>(name: ToolName, execute: (input: I) => Promise<O>): (input: I) => Promise<O>` — logs depth 2 `tool <name>` with `ms`, depth 3 `input` (`formatInput`), depth 3 `result` lines (`summarizeToolResult`), debug payload = raw output; on throw: depth 3 `⚠ error "<message>"` at warn, rethrow.
  - `resolveContext(context, catalog): ResolvedContext & { dropped: { type: "product" | "collection"; handle: string; where: "page" | "history" }[] }` — `dropped` is new; existing fields unchanged.
  - `logContext(context: ShopperContext, resolved: ReturnType<typeof resolveContext>, catalog: { queries: number; handles: number; ms: number; error?: string } | "skipped"): void` — the spec's context block (`shopper`, `page`, `visited` numbered with `⚠ unknown (<handle>) — dropped`, `catalog`); debug payload = `contextPrompt(resolved)`.
  - `loadCatalog` returns `{ catalog, stats }` where `stats` is the `catalog` argument above.
- Agent logging (spec "Chat" section): per step depth 1 `step <n>` with `ms`, depth 2 `tokens in= out= (cached N)`, `finish <reason>`, `text` (quote `model`); display-tool stop shows `finish display tool (stop)`. `runAgent` logs `history` (saved / sent / tool parts dropped) and `flags`, and on a teaser turn a depth-1 `teaser-turn` line naming the tool `teaserTurnPrompt` points to (`getProduct` / `listProducts`). `onError` logs `ERROR agent stream failed error="<message>"`. Debug payloads: the system prompt once, the model messages once.
- Suggestions: `ok attempt=<n> ms=<n>` then `replies` joined with ` | ` (quote model per item); `retry attempt=<n> reason="<message>"` at warn; `✗ failed` at error after 3.
